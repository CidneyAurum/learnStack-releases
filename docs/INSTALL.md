# 安装与开始使用

## 1. 下载和安装

1. 使用 Android 8.0 及以上的手机，打开 [0.2.0 beta 发布页](https://github.com/CidneyAurum/learnStack-releases/releases/tag/v0.2.0-beta.1)。
2. 展开 **Assets**，下载 `learnStack-demo-0.2.0-debug.apk`，也可[直接下载 APK](https://github.com/CidneyAurum/learnStack-releases/releases/download/v0.2.0-beta.1/learnStack-demo-0.2.0-debug.apk)。不要下载 GitHub 自动生成的 Source code 归档来安装应用。
3. 打开 APK；如系统询问，允许当前浏览器或文件管理器安装此来源的应用，再按系统提示完成安装。
4. 打开 learnStack，确认手机可以联网，使用默认服务地址 `https://learnstack.marnhub.com`。

当前安装包是预览用 debug APK，未通过应用商店分发。请只从本仓库发布页取得安装包；发布页的 `SHA256SUMS.txt` 用于核对下载文件是否完整，不能替代来源判断。也可下载[包含安装包与说明的 ZIP](https://github.com/CidneyAurum/learnStack-releases/releases/download/v0.2.0-beta.1/learnStack-demo-0.2.0.zip)，解压后打开其中的 APK。

如果已经安装旧版，先尝试直接覆盖安装。若提示签名不一致，请停止安装并反馈，避免为解决安装错误而直接卸载；卸载可能删除尚未同步的本机资料。若提示不允许降级，请核对安装包版本。

## 2. 注册或登录

- 首次使用：输入自己的邮箱和密码，完成注册。
- 已有账号：选择登录，使用原邮箱和密码。
- 提示“邮箱已注册，请返回登录。”：返回登录即可，已输入的邮箱会保留。

请保管好自己的账号。不要在公开反馈中提供邮箱、密码或登录令牌。

## 3. 配置 AI

1. 打开 **账户** 中的模型配置。
2. 填写模型服务的 HTTPS Base URL 和 API Key，选择服务支持的 OpenAI 兼容协议（Chat Completions 或 Responses）。此时无需先填写模型名称。
3. 点击 **获取模型**，在列表中搜索并选择问答模型；如需图片处理，可另选视觉模型。不会自动选中列表中的第一个模型。
4. 核对选择后，明确点击保存，再使用检查功能核对服务，到 **问答** 发起提问。

获取模型只请求供应商的模型列表，不会保存这次输入的配置或密钥，不生成回答，也不发送学习材料。若服务不支持列表、列表为空或获取失败，可以切换为手动填写模型名称。

缺少必要信息时点击获取或保存会显示具体校验提示；地址栏会说明格式问题，等待处理或服务暂不能保存密钥也会说明原因。获取列表不要求先填写模型名称，保存前需明确选择或填写问答模型名。地址只忽略首尾空白，不会删除内部空白或不可见字符来拼接目标。若仍无法操作，请反馈版本、步骤及实际提示，不要提供 Key。

编辑已有配置时，API Key 留空仅能在服务地址与原配置相同时，使用后端保存的原密钥获取列表；更换地址后必须重新输入密钥。关闭弹窗会清除本次临时密钥和列表，修改地址、密钥或协议后需要重新获取。

配置需要与供应商实际支持的协议和模型一致。模型出现在列表中，不代表已经验证它可以生成回答或识别图片；并非所有声称兼容的服务都已验证。未配置时，仍可使用保存、阅读和人工整理等不依赖模型的路径；AI 请求不会自动使用开发者的共享密钥。

账户中的诊断会分别说明配置是否保存、模型列表是否读取，以及生成与视觉是否验证。列表读取成功不表示生成或视觉能力可用；本页不会为了检查而发起生成。需要使用 AI 时，返回问答或资料处理入口，核对实际输入后再授权。

明确保存时，密钥会通过 HTTPS 交给后端加密保管，不会持久保存到手机本地。详见 [数据与 AI 使用说明](DATA_AND_AI.md)。

## 4. 一个学习目标一个任务

在 **问答** 中选择 **新任务**，为当前学习目标保留独立讨论。新任务不会自动带入其他任务的历史；需要参考其他任务时，明确选择有权访问的固定版本消息，检查预览并授权后再引用。

可以为任务改名、归档或恢复。归档后可阅读，恢复后再继续提问；归档不代表问题已解决、案例已有效或本人已掌握。记录实际尝试与结果后，再决定是否整理为案例。回看历史时，新回复不会强行将你带到底部，可按页面提示回到最新回复。

## 5. 从收集继续到案例

- **收集** 可按待整理、处理中、待确认、已归档筛选。本机保存／同步状态与整理阶段分别显示，筛选或展示去重不会替你删除原件或失败草稿。
- 打开收集详情，依次核对原文、选择整理方式、预览与确认。可人工整理、请求 AI 归档建议，或继续排查形成问题；有对应记录时，可打开当前处理进度、待确认预览或已归档知识。
- 在问题详情选择 **整理为案例**，再选择 **手动填写**、**按已记录行动整理**，或个人问题中的 **预览输入，让 AI 起草**。前两种方式不额外调用模型，AI 起草仍需检查实际输入并明确授权。
- 缺少结果时保留空缺，不把起草或归档写成成功。正式加入知识仍需本人确认或团队审核。
- 在 **案例库** 中按标题查找，先核对条件、做法、来源与已有验证信息，再记录自己的实际使用结果；有效、无效或不适用都可成为后续调整的依据。阅读案例不自动记为本人掌握。

## 6. 邀请别人加入学生团队

1. 创建学生团队空间后，进入该团队的 **账户 → 当前团队** 区域。
2. 由团队所有者选择 **邀请成员 · 生成邀请码**，确认目标团队及邀请角色。普通协作优先使用普通成员角色；维护者权限应按实际需要授予。
3. 生成后查看页面显示的邀请码、有效期与使用限制，按需点击复制，再自行发给受邀者。
4. 受邀者注册或登录后，打开空间选择入口，选择 **通过邀请码加入团队**，输入邀请码。

创建团队不会自动发送邀请。每个邀请码仅供 1 人加入，72 小时内有效，离开显示页面后无法找回。邀请码能赋予加入团队的资格，请只发给你希望加入的人，不要贴到公开 Issue。邀请码过期、丢失或达到使用限制时，请所有者重新生成。

## 7. 查看团队待办与退回理由

在当前团队的审核待办中，**我提交的** 与 **我可审核的** 分开显示。普通成员不能批准提案；维护者不能审核自己的提案，所有者自行通过时会明确记录为 **作者确认**。

审核者核对修改和来源后，可以通过或填写理由退回。提交者可在已退回草稿中查看保存的理由，重新整理后提交新提案。团队审核不会扩大成员对个人学习记录或私人来源的访问权限；来源失效时，相关内容与理由也受失效处理约束。

## 8. 失败、未知结果与服务暂时不可用

当前手机通过 HTTPS 隧道连接试用后端，依赖服务电脑、后端及隧道在线。打开官网不代表后端一定在线，登录、同步和 AI 功能仍需要后端可用。

- 检查手机网络和服务地址；暂时无法连接时，稍后重试。
- 按页面显示的实际保留状态和恢复入口继续。结果未知时先恢复查询，避免重复写入或再次产生模型费用；应用不会自动重放这些请求。
- 出现版本冲突时，先刷新并核对变化，再决定如何修改；恢复历史内容需预览并确认，不会静默覆盖新版本。
- 个人草稿以页面显示的“本机保存／待同步／已同步／失败”等状态为准；待同步时不要卸载应用或清除应用数据。
- 不要通过关闭证书验证、改用陌生服务地址或公开密钥来排查连接问题。
- 团队资料及其受控引用需要在线访问；已失去权限的内容不能通过离线草稿恢复访问。

如果仍然失败，请在 [Issue](https://github.com/CidneyAurum/learnStack-releases/issues) 中提供版本、Android 版本、发生时间、步骤及页面提示，并先遮盖隐私信息。
